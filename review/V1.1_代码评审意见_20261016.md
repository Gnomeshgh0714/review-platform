# V1.1 代码评审意见

## 一、评审版本

- **评审对象**：`dev/` 目录（Django 5.2 后端 + Vue3 前端），2026-10-16 状态
- **评审依据**：`product/prd/V1.1_审稿协作平台_PRD.md`、`product/prd/V1.1_审稿协作平台_技术实施方案.md`
- **评审方式**：蓝军多维度并行审查（安全 / 状态机与并发 / 汇总规则引擎 / API 契约 / 数据模型 / 通知与定时任务 / 前端 共 7 维度）→ 每维度发现由独立核实员对抗性核实
- **评审人**：产品评审专员（本轮由开发侧 Claude Code 按评审专员角色定义代行；按角色准则只列问题、不附解决方案）
- **问题总数**：137 条（致命 13 / 严重 54 / 一般 60 / 建议 10；跨维度同一问题的重复表述未合并，裁决时可归并）

## 二、总体评价

平台主流程（状态机转换、规则引擎汇总、并发提交控制）在 36 项单元测试与全链路冒烟下可跑通，工程骨架完整。但本轮蓝军评审发现的问题表明：**当前实现距离可上线状态有实质差距**，问题高度集中在三类：

1. **授权体系形同虚设**：除个别端点外，全平台没有对象级权限校验。存在两条完整提权路径（任意登录用户可重置编辑部账号密码；任意用户可自报 roles 提权为 EDITOR），双盲保护在 API 层完全失效，任意登录用户可枚举下载全部稿件。
2. **前后端契约全面脱节**：前端按一套想象中的接口开发，从未与后端联调。分配审稿人、创建任务、提交审稿意见、终审决策等核心页面的请求体字段名/结构与后端不一致，实际操作必然 400/404——即前端目前**基本不可用**。
3. **关键数据落地断裂**：终审决策字段经 API 录入后从不落库（响应显示的是内存对象，具有欺骗性）；知识库自动归档链路零调用，PRD 的知识库闭环不存在；汇总报告中存储审稿人真实身份，匿名化过滤键名与实际数据键名不符。

另有规则引擎多处与 PRD/技术方案的规则表不一致（Rule-4 附加了方案外的限制条件、Rule-5 遗漏前置条件、分歧标注缺推荐结论级对立检测等）。
