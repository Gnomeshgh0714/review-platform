# AC 验收映射表：54 条 PRD 验收标准 × 测试用例对照

> 用途：给产品验收方一个「不用人工全测」的硬依据。PRD V1.1 §2.7/§3.7/§4.7/§5.7 共 54 条验收标准（AC-T 13 + AC-F 12 + AC-S 14 + AC-K 15），本表逐条标注背书用例——哪条 AC 由哪个测试文件哪条用例覆盖、哪些只能人工走查。配合 `V1.3_产品定版验收清单_20261023.md` 使用：先读本表判断哪些 AC 可直接信任测试基线，再对「人工走查」条目做现场验证。
>
> 覆盖口径：后端 184 项（`cd dev/backend && python manage.py test apps`）、前端 16 项（Vitest）、E2E 25 项（`scripts/e2e_smoke.py`），均为 2026-10-23 实测全绿基线。
>
> 标记说明：**自动** = 有自动化用例直接断言，验收方可免测；**部分** = 核心逻辑有用例，个别子项缺口需人工补验；**人工** = UI 交互/邮件/数据准备类，需现场走查。

## 五、覆盖统计与结论

| 覆盖档 | 条数 | 占比 |
|--------|------|------|
| 自动（免测） | 33 | 61% |
| 部分（核心有测+小缺口） | 16 | 30% |
| 人工（需走查） | 5 | 9% |

- **自动 33 条**：验收方核对用例存在并信任 184/16/25 基线即可，无需重测。
- **部分 16 条**：缺口集中在三类——邮件通道（AC-T-02/T-12，全局缺）、`process_scheduled` 时间推进链（AC-T-06/T-08）、个别 UI 标注与上限断言（AC-S-12、AC-K-15 等）。建议按「免测核心+现场补验缺口」处理。
- **人工 5 条**：模板管理四条（AC-F-08/09、AC-K-08/09）是最大的人工块，加编辑部看板 UI（AC-T-05）；AC-F-06 中断恢复与 AC-K-14 种子抽查已在「部分」档单独列出。若要压缩人工量，优先给模板管理补一组后端 ViewSet 测试，AC-F-08/09/K-08/K-09 四条可整体转「部分」档。

**与验收清单的衔接**：本表「部分」档中的两个观察点（O-2 score_range no-op、O-4 重复提交分支，后者对应 `test_duplicate_submit_rejected` 与分配状态门的交互）即定版验收清单 5.1 节待裁决项——裁决为「变更语义」时，对应测试断言需同步改（决策 #017 已备案此纪律）。
