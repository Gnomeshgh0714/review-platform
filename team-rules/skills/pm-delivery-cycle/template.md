# PM 交付周期 · 产出物骨架

供 pm-delivery-cycle 各阶段直接套用的骨架。占位符用 `<...>`；带 ⚠ 的行按项目实际删改。

## 一、代码评审报告骨架

```markdown
# V<x> 代码评审意见（评审轮 <n>）

## 一、评审版本
- **评审对象**：<代码目录/范围>，<日期> 状态（main <commit>）。<上轮清账背景一句话>
- **评审依据**：<上轮评审报告、决策日志编号区间、清账 diff 范围>
- **评审方式**：<复核方式：diff 逐行审读 / 通道级扫描清单 / 修复间互踩交叉 / 测试基线实测>
- **评审人**：<角色>（按角色准则只列问题、不附解决方案）
- **问题总数**：<n> 条（致命 <n> / 严重 <n> / 一般 <n> / 建议 <n>）

## 二、总体评价
<对上轮修复的复核结论 + 通道级扫描结果表 + 测试基线 + 收敛趋势判断>

## 三、核实状态说明
<审读范围、扫描项、标记口径（✓核实成立 / ◐抽查属实）>

## 四、问题清单（按严重程度排序）
### 致命（<n> 条）
**<n>. <问题标题>**
- 位置：`<文件>:<行>`（<波及范围>）
- 严重程度：<级>　|　核实：✓核实成立（<方式>）
- 问题描述：<现象 + 触发场景 + 影响>
- 备注：<非阻断理由 / 关联事项>
- **处置：<已修复（日期与提交）/ 记入遗留 / 暂缓原因>**

### 建议（<n> 条）
<同结构，建议级可适当从简>

## 五、结论
1. <评审周期闭环判定>
2. <本轮发现定性与是否阻塞定版>
3. **建议处置**：<逐条去向；提请验收定版 / 遗留排期>
```

## 三、现状锁定观察点·测试注释骨架

语义待裁决的行为，测试按现状断言并加注释（不留在报告里空转）：

```python
# --- 文件头「既有行为锁定」段 ---
既有行为锁定（断言现状，非缺陷判定）：
- <行为描述>（<代码位置>）。
  若后续产品决定「<可能的变更方向>」，需同步更新断言。

# --- 测试方法 ---
def test_<现状行为名>(self):
    """现状锁定：<行为>（见文件头注释）"""
    ...
    self.assertEqual(<现状期望>)

# --- 裁决变更后的同步改法（测试同步纪律）---
# 1. 方法改名：test_<现状行为名> → test_<新语义名>
# 2. 断言改为新语义期望
# 3. 文件头注释改口径并注明裁决来源与日期
```

## 八、多角色分工骨架

skill 正文说「适用多角色协作（多 agent 或人机混合）」，此处给最小角色实例化，供外部项目复用（不必依赖 pm-team 原始角色准则文件）。从 pm-team 团队协作规则的角色权责矩阵裁剪而来，覆盖交付周期四角色：

```markdown
# 交付周期角色分工（最小四角色）

## 开发侧（执行者）
- 职责：按批实现修复/裁决落地；每批自测（后端/前端/构建/E2E 四组数字）
  + 环境还原 + 决策日志备案（骨架二）
- 边界：修复方案由自己独立设计（评审只给问题不给方案）；密钥永不入代码

## 评审侧（对抗者）
- 职责：只列问题、不附解决方案；发现四档分级，每条含位置/场景/严重度理由；
  原始发现全量留档；修复批复核先问「能否绕过」再做通道级扫描
- 边界：仅评审不执行；每轮至少覆盖逻辑漏洞/边界遗漏/风险点三类

## 独立审核（复现者）
- 职责：验收材料独立复现——测试基线重跑、留痕逐格比对、
  口径误差照实修正并回写（骨架五）
- 边界：不由产出者自证；审核记录附可复现命令与环境还原声明

## 产品裁决（签核者）
- 职责：定版清单逐项勾选落签（骨架四）；观察点逐项给「维持/变更」结论；
  裁决当日转落地批，不停留在文档上
- 边界：对结论拍板，不干预实现细节
```

同会话多 agent 实施要点：①角色切换用「重述任务+角色边界」而非续写对话，
避免评审侧看到开发侧的方案辩护；②角色准则写进各角色提示词，职责冲突
交产品裁决；③人机混合时，人工角色（签核/裁决）保留否决权，agent 角色
只提请不代签。
