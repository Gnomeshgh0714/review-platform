# 团队协作规则

> 本文件是团队日常运作的操作手册，所有角色必须严格遵守。修改本文件需经产品总监审核 + 人工确认。

---

## 1. 角色权责矩阵

| 角色 | 核心职责 | 输出物 | 权限边界 |
|------|---------|--------|---------|
| 产品总监 | 全局把控、最终决策、团队管理、组织进化 | 决策记录、终审意见、复盘报告 | 跨角色裁决、流程把控，不干预专业细节 |
| 用户研究专员 | 用户洞察、竞品分析、反馈整理 | 用研报告、竞品分析报告、用户画像 | 仅负责用研环节，不直接输出产品方案 |
| 产品设计专员 | 需求拆解、PRD撰写、交互设计 | PRD文档、交互原型、功能流程图 | 按用研输入设计，不自行编造用户需求 |
| 增长运营专员 | 指标体系、增长方案、发布运营 | 指标定义文档、增长方案、运营计划 | 按产品定稿制定运营方案，不擅自改产品 |
| 产品评审专员 | 反向评审、风险识别、漏洞挖掘 | 评审意见、风险清单、改进建议 | 仅评审不执行，必须提出实质性反对意见 |

## 2. 标准工作流

```
① 用研输入 → ② 产品设计 → ③ 评审攻防 → ④ 总监终审 → ⑤ 落地执行 → ⑥ 复盘优化
```

### 各环节交付标准

| 环节 | 负责人 | 交付物 | 交付标准 | 时限 |
|------|--------|--------|---------|------|
| 用研输入 | 用研专员 | 用研报告 | 含目标用户、核心痛点、竞品对比、需求优先级排序 | 接到任务后1轮对话内 |
| 产品设计（含提交前自检） | 设计专员 | PRD + 流程图 + 自检清单 | 含功能清单、交互逻辑、数据结构、边界条件、验收标准；**提交前须完成5项自检**（见下方自检清单） | 接到用研报告后1轮对话内 |
| 评审攻防 | 评审专员 | 评审意见 | 至少提出3条实质性问题，覆盖逻辑漏洞、边界遗漏、风险点 | 接到PRD后1轮对话内 |
| 总监终审 | 产品总监 | 终审决策 | 明确通过/打回/修改，打回须说明原因和修改方向 | 接到评审意见后1轮对话内 |
| 落地执行 | 设计专员 | 实施方案 | 含技术方案、任务拆解、时间节点 | 终审通过后1轮对话内 |
| 复盘优化 | 产品总监 | 复盘报告 | 至少1个可优化点 + 1个可沉淀技能 | 每轮迭代结束后 |

### PRD提交前自检清单（最低5项）

设计专员在提交PRD进入评审前，须逐项自检并标注结果：

1. 数据模型是否覆盖所有引用的实体类型（无悬空外键）
2. 状态机是否所有状态有出口、无死锁/不可达路径
3. 跨实体引用的外键是否指向已定义实体
4. 边界声明与实际功能实现是否一致（无隐性突破P0边界）
5. 并发场景是否定义数据一致性策略

> 自检结果随PRD一并提交评审专员参考。自检发现的问题应在提交前修复，未修复的标注为"已知风险"。

### 阶段交接清单

每个阶段交付时附带结构化交接信息，包含：
- 交付物文件路径
- 关键数据摘要（如PRD行数、功能数、实体数、已知问题数）
- 下游需关注的重点
- 已知遗留问题（如有）

## 3. 决策机制

- **日常专业问题**：由对应角色负责人决策，记录在当轮工作日志中
- **跨角色分歧**：由产品总监裁决，写入 `/team-rules/决策日志.md`
- **重大架构/方向变更**：必须提交人工确认，未经确认不得执行

## 4. 文件归档规范

### 目录结构
```
项目根目录/
├── IDEA.md                    # 项目宪章（最高优先级）
├── team-rules/                # 团队规则与决策日志
│   ├── 决策日志.md
│   └── 团队协作规则.md
├── product/
│   └── roadmap/               # 迭代规划与路线图
├── retrospective/             # 复盘报告
└── (各角色输出物按轮次归档)
```

### 命名规范
- 文件命名：`日期_主题.md`，如 `20260716_第一轮迭代路线图.md`
- 日期格式：YYYYMMDD

### 留痕规则
- 所有正式输出必须写入文件，禁止仅在对话中传递
- 所有评审意见、修改记录必须留痕，可追溯
- **禁止删除或覆盖任何历史输出、评审意见、决策记录**

### 目录规范变更流程
1. 角色定义下发后，如需调整目录规范，由产品总监发起决策（写入决策日志）
2. 决策内容包含：新目录路径、命名规范、历史文件处置策略（标注为归档/迁移）
3. 变更后1轮对话内完成所有相关文件的标注
4. 旧路径文件在头部标注"⚠️ 本文件已迁移至[新路径]，此为历史归档保留"

## 5. 红线禁令

1. 禁止角色越权，禁止产品设计直接改评审意见
2. 禁止删除任何历史记录、评审意见、决策日志
3. 禁止未经人工确认修改团队核心架构与协作规则
4. 禁止跳过评审环节直接输出最终方案
5. 禁止违背 IDEA.md 约定的功能边界与技术约束

## 6. 能力升级路径

| 等级 | 标准 | 验收方式 |
|------|------|---------|
| L1 | 能按流程走完单个需求输出，不跳步、不遗漏 | 完整走完一轮"需求→PRD→评审→定稿" |
| L2 | 能自主发现问题、主动优化输出质量 | 评审攻防机制有效，能发现实质性问题（严重问题占比≥20%） |
| L3 | 能自主沉淀技能、优化工作流程 | 自主完成复盘，沉淀可复用Skill |
| L4 | 能自主调整分工、适应新的产品方向 | 更换产品方向后快速适配输出合格方案 |
